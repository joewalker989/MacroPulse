# MacroPulse 9.7 — reviewed food logging

Roadmap items **13–18 and 20** are implemented. Item 19, actual AI meal-photo activation and acceptance, remains pending server provider credentials and a real consented request. Local matching and OCR are not presented as AI integration.

- Combined saved-food search tolerates punctuation, accents, one missing/extra/substituted letter, adjacent transpositions and a small disclosed ingredient-synonym list. Users can save aliases against an exact food/source/serving identity. Matches disclose their reason; discovery never equates nutrition records or logs a meal.
- Preferred portions fill future saved-food, sourced-food and multi-select drafts. A reviewed conversion records mass or volume per listed serving and its evidence. Exact g/kg/oz and ml/l/US-fl-oz conversions retain dimensions. Unknown household servings need food-specific evidence; known mass/volume bases cannot be overridden. Preferences can be forgotten without changing foods or diary records.
- Calorie explanations compare listed energy with the 4/4/9 macro arithmetic. They disclose possible label/source differences, do not infer the cause and retain listed nutrition.
- Duplicate diary review shows both complete source/serving names and macros. Explicit archiving removes only the reviewed entry and its linked nutrient/cost/note records from active totals. The archive retains exact originals for restoration. Restoration refuses ID conflicts. Archives and their cross-module links require a whole-app sync choice when devices differ, with existing encrypted recovery retained.
- A multi-food description tool supports fractions, explicit amounts/units, quoted names, saved aliases and choices among ambiguous source/serving matches. Unknown foods and unsupported conversions block logging. Every portion is previewed, then the complete meal and supported source nutrients are saved together. Duplicate lines must be combined rather than silently collapsed. No AI or automatic nutrition inference is involved.
- Nutrition-label review displays the original selected image locally with zoom while text/values are corrected. Selection does not start OCR, upload the image or save food. Changing the image clears the old draft. File changes are disabled during OCR so recognized values cannot be shown beside a different image.
- The optional food-tools extension is lazy and versioned. The first write retains exact prior raw JSON in a separate recovery key. Failed storage, validation and stale tabs preserve original data; only changed top-level fields are applied. Existing feature modules, progress photos, unknown fields, daily targets and offline support remain intact.

Validation: **168 unit tests and 23 browser suites**, including archive/restore with linked data, whole-ledger sync review, dimension-safe conversion, ambiguity gates, original-image display without network requests, preferred portions, exact recovery, quota rollback, offline reload, stale tabs and mobile layout. Deployment verification records the published hashes and live food-tools browser test separately.

Items 8, 10 and 19 retain their documented external/user-device acceptance dependencies. The next implementation stage is recipe/planning items 21–30; the full list remains in ROADMAP_PROGRESS.md.
